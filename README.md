# SelfAgent

Мультиагентная система на Pydantic AI, которая анализирует проект, предлагает небольшие улучшения, создаёт кандидатную Git-ветку, проводит независимое ревью и проверяет изменения в Docker-контейнере. Успешные кандидаты автоматически сливаются в локальную ветку `main`.

В системе есть роли планировщика, разработчика и ревьюера, а ревьюер делегирует отдельную проверку безопасности через Pydantic AI Harness. Планировщик может использовать низкоконтекстный OpenAI Web Search; инструкция просит выполнять не более одного поиска за цикл, а бюджет резервирует до трёх центов на поиск и ограничивает число запросов. Разработчик возвращает изменения только для файлов внутри `src/` и `tests/`; новые файлы разрешены. Кандидат собирается и тестируется без сети и без секретов в read-only контейнере. При провале ревью или проверки кандидатная ветка удаляется. Бюджет каждого вызова ограничен остатком дневного лимита, а фактические расходы хранятся локально в SQLite.

**Logfire не используется.** Журналы Loguru выводятся в консоль и создаются в `logs/YYYY-MM-DD/ИмяКласса.log`. Они показывают этапы работы, вызовы инструментов, стоимость и краткие объяснения, возвращённые агентами. Скрытые внутренние рассуждения модели не выдаются API и не журналируются. API-ключ не выводится приложением в журналы. Отправка включена и использует указанный SSH-ключ после прохождения ревью и Docker-тестов.

## Требования

- Python 3.15
- pip
- Docker Desktop с запущенным Linux Engine
- Git
- новый ключ OpenAI API с доступом к `openai:gpt-6-luna`

## Сборка и установка вручную

В PowerShell из корня репозитория выполните:

```powershell
py -3.15 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -e ".[dev]"
Copy-Item .env.example .env
```

Откройте `.env` и задайте `OPENAI_API_KEY`. Ключ хранится только локально и не попадает в Git. Остальные параметры, включая модель, дневной бюджет, журналирование и Git, описаны комментариями в `.env.example`.

## Ручной запуск

Сначала проверьте, что Docker Engine доступен, затем соберите образ:

```powershell
docker compose build
```

Запустить один цикл улучшения:

```powershell
python -m selfagent
```

Запустить не более трёх последовательных циклов:

```powershell
python -m selfagent --cycles 3
```

Повторять цикл до отклонения кандидата или исчерпания дневного бюджета:

```powershell
python -m selfagent --continuous
```

Показать расходы за сегодня:

```powershell
python -m selfagent --budget
```

Для запуска приложения в контейнере:

```powershell
docker compose run --rm selfagent
```

Агенты используют сеть для поиска открытой информации. Кандидаты собираются отдельно из рабочей ветки и проверяются в контейнере без сети. Контейнер проверки получает только код проекта, не получает `.env` и работает с read-only файловой системой.

## Настройка отправки в GitHub

`GIT_PUSH_ENABLED` управляет отправкой успешных циклов в `GIT_REMOTE_URL` и по умолчанию включён. Путь к ключу задаётся в `GIT_SSH_KEY_PATH`; по умолчанию используется `~/.ssh/dunno-deploy`. Перед отправкой изменения проходят ревью и изолированные тесты Docker.

## Разработка в VS Code и PyCharm

Откройте каталог проекта как обычный Python-проект и выберите интерпретатор `.venv`. Рекомендуемый стиль форматирования задаётся в `pyproject.toml` (`black`, длина строки 88). Зависимости устанавливаются через pip; проверочные инструменты доступны через `[dev]`.
